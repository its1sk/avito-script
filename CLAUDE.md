# Avito userscript — контекст проекта

Общайся по-русски, просто и по делу. Главное для пользователя — **скорость** скрипта. Если что-то сильно замедляет, сразу говори об этом и предлагай исправление. Не выпускай новые версии «на всякий случай»: сначала найди настоящую причину проблемы.

## Что это
Userscript для Tampermonkey «Avito — скрыть продавцов + мои поиски». Текущая версия **v6.2**. Файлы с постоянными именами (не менять — на них ссылаются `@updateURL`/`@downloadURL`):
- `avito.user.js` — исходник, версия для ПК;
- `avito-mobile.user.js` — для телефона, тот же код, сжатый terser (собирается `sh build.sh`);
- `avito-v4.9-mobile.user.js` — переходная копия мобильной (по этой ссылке могла стоять v4.9). Удалить, когда телефон обновится на v5.0+.

**Обновление через GitHub.** В шапке `@updateURL`/`@downloadURL` → raw-ссылка на `main`. Tampermonkey сам проверяет обновления (по умолчанию раз в сутки; вручную — «Проверить обновления» в меню TM или кнопка «⬆️ Обновить» внизу панели ⭐, она открывает raw-ссылку). Обновление идёт в тот же скрипт, данные GM сохраняются. Поэтому новая версия доходит до пользователя только после слияния в `main`. Raw GitHub кэширует до ~5 минут.
- Телефон: https://raw.githubusercontent.com/its1sk/avito-script/main/avito-mobile.user.js
- ПК: https://raw.githubusercontent.com/its1sk/avito-script/main/avito.user.js

Старый способ тоже работает: «Утилиты → Импорт из файла» → «Обновить», в тот же скрипт. Хранилище GM привязано к скрипту: если поставить новый скрипт рядом (а не обновить), данные пропадут. После обновления открытые вкладки Авито нужно перезагрузить, иначе в них продолжит работать старый код. Номер версии и число поисков видны внизу панели ⭐.

**Слияние PR — самому, без подтверждения пользователя** (разрешил 17.10: «сливай сам»). Порядок: изменения → `sh build.sh` → тесты → коммит → push → PR → сразу merge в `main` → сказать пользователю «⬆️ Обновить» и перезагрузить вкладки. Не сливать то, что не прошло проверку.

Сборка мобильной версии: `sh build.sh` (шапка берётся до `==/UserScript==`, ссылки обновления подменяются на мобильный файл, заодно обновляется переходная копия).
При каждой версии поднимать `@version` и `CODE_VER`. Вкладка, увидевшая более новый `CODE_VER`, перестаёт проверять в фоне.

## Требования к поискам
- Вся Россия, только с доставкой (`d=1`), сортировка по дате (`s=104`), цена до 10 000 ₽.
- Одежда XS–M (42–48), обувь 41/42/43.
- Только фильтр по бренду, без текстового поиска. Исключение — Energie: его нет в фильтре Авито, ищется по тексту (`q=energie`).
- **«Новое с биркой» не показывать совсем** (пользователь, 19.10): `feedHideReason` → `'newtag'`, на страницах поиска тоже; настройка `noNewTag` в ⚙️, по умолчанию вкл. Такие вещи не попадают ни в ленту, ни в паль, их описания не качаются.
- В одном поиске не больше 7 кодов брендов, это лимит Авито.

## Устройство скрипта
- **Данные** берутся из JSON на странице: `{"id":…,"categoryId"…}`, `sortTimeStamp`, `iva.FashionParamsStep`. Это строка вида «Состояние · Размер · Бренд». Блок `extraBlockItems` (объявления из других городов) пропускается.
- **Лента.** Объявление новое, если `ts > lastTs` поиска. Первая проверка поиска только запоминает текущую выдачу. Непросмотренное из ленты не удаляется.
  - Объявления со старой датой заносятся в `seen` и в журнал `skipLog`. На журнале работает кнопка «⏪ Вернуть пропавшие».
  - «✓ Скрыть» ставит `seenAt` на само объявление в ленте (и пишет в `seen` поиска). `seen` ограничен 500, поэтому без `seenAt` при «Всё просмотрено» на 600+ объявлений одного поиска часть оставалась в ленте.
  - Цена изменилась у объявления в ленте → `oldPrice`, в карточке «📉 было …».
  - Если вещь скрыта как «чужой бренд/размер» для своего поиска, а другой поиск находит её как свою, она переходит к этому поиску.
- **Скорость.**
  - Проверка держит состояние в памяти (`newCheckState`) и сохраняет пачкой раз в 3 с. Объявление, которое уже в ленте и не изменилось, ленту не переписывает.
  - Признаки пали при разборе выдачи кэшируются (`palFeaturesMemo`): одни и те же объявления приходят при каждой проверке.
  - В ленте «✓ Скрыть», «🚫 Продавец», «✅ Не паль» убирают карточку на месте, без перерисовки; запись в хранилище — пачкой (`queueHide`, `markShown`). Есть «Отменить».
  - Чтение идёт через кэш `loadRO` / `loadFeedRO`; их результат нельзя изменять.
  - Страница поиска пересчитывается только при смене набора карточек.
  - Лента рисует карточки по 100, дальше подгружает при прокрутке.
  - Дочитывается до 8 страниц, но только если вся предыдущая страница новая.
- **Паузы Авито.** Ручная проверка сама ждёт и продолжает (60/120/180/240 с). Фоновая проверка просто останавливается.
- **Фоновая проверка** идёт и при открытой ленте: найденное появляется само; если лента пролистана, вместо сдвига — кнопка «⬆ Новых: N». Число новых — в заголовке вкладки.
- **⚙️ Настройки ленты** (`amsOpts`): 🔔 уведомления (`GM_notification`, когда вкладка не в фокусе), 🌙 проверка в скрытой вкладке (по умолчанию выкл.), сортировка «свежие / дешёвые».
- **❤️ Отложенные** (`favItems`, до 500): копии объявлений, не зависят от ленты. Если вещь снова попалась в выдаче — цена обновляется, видно «было …». Входят в перенос и копии.
- **Клавиши в ленте (ПК):** J/K — следующее/предыдущее, O/Enter — открыть, X — скрыть, F — отложить.
- **Фильтры ленты.** Стоп-слова (общие и у каждого поиска), скрытые продавцы, размер и бренд по строке параметров, стелька по тексту.
  - Стоп-слова ищутся и в полном описании (`itemText`), латинские буквы, похожие на русские, считаются русскими (`findWord`): «пoмoжeм» с латинской «o» = «поможем». В общих стоп-словах пользователя — фразы магазинов пали («lux», «люкс», «размеры в наличии», «подобрать размер»…).
- **Детектор пали.** Вкладка «Похоже на паль», объявления не удаляются.
  - Нужно минимум два признака и 5 баллов.
  - Слабые признаки вместе дают не больше 3 баллов: новое с биркой, магазин в имени продавца, завершённые объявления.
  - Сильные признаки:
    - много размеров;
    - «реплика»;
    - продавец часто встречается в выдаче (от 5, 10, 20 раз);
    - одинаковые новые вещи по одной цене;
    - перевыложено и вещь новая;
    - вещь не в своей категории.
  - **Главный признак — много размеров в наличии** (+4: «новое» + много размеров = паль). Ловится список «S-M-L-XL», «В наличии: S, XL, XXL», таблица по строкам «37EU-23,5см» / «S - 46», фразы «размеры по стельке», «подберём по росту и весу».
  - Фразы магазинов пали (со скриншотов пользователя): «пишите в ЛС», «навесные бирки», «фирменная упаковка», «производство Стамбул/Турция», «качество на высоте», «эксклюзивный товар», «возврат без лишних вопросов», «никаких дешёвых аналогов». Из настоящих описаний 17.10: «при заказе пишите (размер)», «наш Telegram», «заказывал с Китая», «оптовая/оптом и в розницу»; таблица размеров в строку «41(26см),42(26,5см),43(27,5)» (`SZ_INLINE_SHOE`).
  - В описаниях часто латиница вместо кириллицы по всему тексту («Прoдaм сумку Аrmani») — и у пали, и у перекупщиков ношеного (+3, «латинские буквы вместо русских»).
  - **Полные описания.** В выдаче описания почти нет (в файле пользователя было у 7 из 100). Поэтому `descRun` скачивает страницу объявления **с cookie пользователя** (`credentials: 'include'`). Без cookie Авито отвечает **439 «Доступ ограничен: проблема безопасности»** — проверено 17.10, анонимно не работает. Пользователь разрешил cookie: «на рекомендации плевать». Качаются: новое; «Отличное» и т.п. — только у продавцов, похожих на магазин (имя, ≥300 завершённых, ≥5 раз в выдаче); всё отмеченное «🇨🇳 Паль» (описание дописывается в `palMissed` как `featWithDesc`); вся вкладка пали — в конце очереди, без ограничения по возрасту (для файла анализа). Порядок: отметки → обычная лента (невиденное раньше) → паль. Обычная лента — не старше 72 ч; по 12 за раз, раз в 2,5–4 с; при паузе Авито (403/429/439) — 15 мин и дальше вдвое. Результат — `fullDesc` (до 1500 знаков) и `descAt`, счётчики — в `descState` (видны во вкладке пали и в ⚙️). Отключается в ⚙️.
  - **«⚡ Загрузить описания сейчас»** (вкладка пали и ⚙️): `descRun({stop, onProgress})` — вся очередь, по одному запросу, пауза 1–1,7 с, запись ленты раз в 12; не смотрит на паузу и видимость вкладки, ждёт идущую проверку поисков; на 403/429/439 останавливается и ставит обычную паузу. Окно с прогрессом и «⏹ Остановить».
  - Как извлекается описание: только `data-marker="item-view/item-description"` / `itemprop="description"`; затем `"description":"…"` в JSON — то, у которого рядом (±3000) название вещи, иначе рядом номер (±60000), самое длинное — как есть, экранированное в JS-строке, в `&quot;` и в `__initialData__` (%22); затем `og:description`. Служебные тексты (`isJunkDesc`: «Только в пунктах Авито», «После получения товара», короче 30 знаков) не берутся.
  - **v5.3–5.6 записывали блок доставки вместо описания**: общий поиск по `data-marker="…description…"` и «самое длинное рядом с номером». В файле 17.10 у 165 из 216 скачанных было «Только в пунктах Авито» / «После получения товара». v5.7 стирает такие и качает заново. В `descState.diag` теперь есть `markers` (все `data-marker` с «descr») и `cands` (все `"description"` на странице: начало, длина, рядом ли название/номер).
  - Ускоренный режим с 2 запросами одновременно получил от Авито **403 «Доступ ограничен: проблема с IP»** — с v5.7 он по одному, пауза 1–1,7 с.
  - **v5.2 на живом Авито не скачала ни одного описания** (файл анализа 17.10: ok 0, fail 0, две паузы). Тогда пауза включалась, если в первых 30 000 знаках есть «captcha», а описание не нашлось. Это могло быть служебное слово на обычной странице, а могла быть настоящая проверка Авито для запросов без cookie. С v5.3 блокировка — только 403/429, «робот/captcha/доступ ограничен» в `<title>` или короткая страница; иначе это «страница без описания». После 8 неудач подряд — пауза 6 ч. Что ответил Авито, пишется в `descState.diag` (статус, длина, заголовок, какие метки есть, фрагмент рядом с «captcha», начало HTML) — он уходит в файл анализа. Кнопка «🔬 Проверить загрузку описания» в ⚙️ показывает это сразу.
  - Из файла анализа 17.10 (27 отметок «паль»): частые признаки — «type» в названии (пользователь: само по себе не повод), «В наличии» в названии и в имени продавца («god | ВСЕ В НАЛИЧИИ», состояние «Отличное», 4612 завершённых). Главное, по словам пользователя, — описание.
  - **Отметки для анализа.** «🇨🇳 Паль» на обычной карточке (`palMissed`, до 300): вещь сразу в пали, продавец +4 ко всем его вещам, описание дозагружается. «✅ Не паль» сохраняет снимок ошибки (`palWrong`). Кнопка «📊 Файл для анализа» (вкладка пали и ⚙️) сохраняет `{kind:'ams-palreport', missed, wrong, palTab (вся вкладка), normal (до 400), sellers, global, descState}` — у каждого объявления полные данные, `feat` (баллы, признаки), `verdict`, статистика продавца. Формат как у переноса (AVITO-SYNC2: deflate-raw + base64); расшифровка: `zlib.decompress(base64, -15)`.
  - Пользователь отказался: от фильтра по цене и от признака «много брендов». «type» в названии сам по себе — не повод считать палью (главное — описание).
- **Объединение поисков.** Импорт `{merge:[{kind,name,url,ban,from:[старые ссылки]}]}`.
  - Новый поиск забирает у старых `seen` и `lastTs`, объявления ленты и журнал.
  - Перед заменой скрипт проверяет по одному поиску каждого вида, понял ли Авито фильтры. Для аксессуаров проверка идёт по выдаче, потому что Авито не возвращает их фильтры в ответе.
- **Плашки ленты** — по брендам из объявлений, в одну строку.
- **Перенос ПК↔телефон.** 📤 Перенос → файл (полная копия, импорт заменяет всё). Резервные копии хранятся в localStorage сайта, «🗂 Копии». Общей синхронизации нет; обсуждали Яндекс Диск или GitHub Gist, не делали.

Теперь `enforceRemoved` при каждом запуске чистит поиски по `PLAN58.removeIds` и названиям (без запросов), а `feedHideReason` скрывает вещи этих брендов по бренду из объявления (`'removed'`), кто бы их ни нашёл.
- **Levi's — только джинсы** (v6.2, `addLevis62`, флаг `plan62`): «👕 Levi's — джинсы» = подраздел джинсов (176=752) + бренд 1689692 + размеры XS–M. Аксессуары, сумки и другая одежда Levi's не нужны — перестройка пропускает поиски с параметром 176 при дополнении аксессуаров.
- Если для поиска чего-то не хватает (подраздел, код) — **спросить пользователя**, а не обходить фильтром по названию: он знает ссылки Авито (20.10: «если тебе чего-то не хватает — спрашивай, прежде чем делать»).
- Тесты в jsdom идут медленно из-за его самописного `URL` (секунды на разбор сотен ссылок) — в браузере это мгновенно, не путать с тормозами скрипта.
