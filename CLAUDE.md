# Avito userscript — контекст проекта

Общайся по-русски, просто и по делу. Главное для пользователя — **скорость** скрипта. Если что-то сильно замедляет, сразу говори об этом и предлагай исправление. Не выпускай новые версии «на всякий случай»: сначала найди настоящую причину проблемы.

## Что это
Userscript для Tampermonkey «Avito — скрыть продавцов + мои поиски». Текущая версия **v7.7**. Файлы с постоянными именами (не менять — на них ссылаются `@updateURL`/`@downloadURL`):
- `avito.user.js` — исходник, версия для ПК;
- `avito-mobile.user.js` — для телефона, тот же код, сжатый terser (собирается `sh build.sh`);
- `avito-v4.9-mobile.user.js` — переходная копия мобильной (по этой ссылке могла стоять v4.9). Удалить, когда телефон обновится на v5.0+.

**Обновление через GitHub.** В шапке `@updateURL`/`@downloadURL` → raw-ссылка на `main`. Tampermonkey сам проверяет обновления (по умолчанию раз в сутки; вручную — «Проверить обновления» в меню TM или кнопка «⬆️ Обновить» внизу панели ⭐, она открывает raw-ссылку). Обновление идёт в тот же скрипт, данные GM сохраняются. Поэтому новая версия доходит до пользователя только после слияния в `main`. Raw GitHub кэширует до ~5 минут.
- Телефон: https://raw.githubusercontent.com/its1sk/avito-script/main/avito-mobile.user.js
- ПК: https://raw.githubusercontent.com/its1sk/avito-script/main/avito.user.js

Старый способ тоже работает: «Утилиты → Импорт из файла» → «Обновить», в тот же скрипт. Хранилище GM привязано к скрипту: если поставить новый скрипт рядом (а не обновить), данные пропадут. После обновления открытые вкладки Авито нужно перезагрузить, иначе в них продолжит работать старый код. Номер версии и число поисков видны внизу панели ⭐.

**Слияние PR — самому, без подтверждения пользователя** (разрешил 17.10: «сливай сам»). Порядок: изменения → `sh build.sh` → тесты → коммит → push → PR → сразу merge в `main` → сказать пользователю «⬆️ Обновить» и перезагрузить вкладки. Не сливать то, что не прошло проверку.

Сборка мобильной версии: `sh build.sh` (шапка берётся до `==/UserScript==`, ссылки обновления подменяются на мобильный файл, заодно обновляется переходная копия).
При каждой версии поднимать `@version` и `CODE_VER`. Вкладка, увидевшая более новый `CODE_VER`, перестаёт проверять в фоне.

## Требования к поискам
- Вся Россия, только с доставкой (`d=1`), сортировка по дате (`s=104`), цена до 10 000 ₽.
- Одежда XS–M (42–48), обувь 41/42/43.
- Фильтр по бренду, если бренд есть в каталоге (`avito-brands.json`); если нет — поиск по слову (`q=…&cd=1`): Energie, Dolani, Momotaro и ~140 слов из памятки (v6.9).
- **«Новое с биркой» не показывать совсем** (пользователь, 19.10): `feedHideReason` → `'newtag'`, на страницах поиска тоже; настройка `noNewTag` в ⚙️, по умолчанию вкл. Такие вещи не попадают ни в ленту, ни в паль, их описания не качаются.
- В одном поиске не больше 7 кодов брендов, это лимит Авито.

## Устройство скрипта
- **Данные** берутся из каталога выдачи (`catalogOf`: объект `"catalog":{…}` — и в HTML, и в JSON): `catalog.items` с `type: 'item'` — выдача, `catalog.extraBlockItems` (другие города) пропускается. **Карусель рекомендаций** (`type: 'itemsCarouselWidget'`, ~32 случайных вещи не по фильтрам, ~1,2 МБ) — не выдача: до v7.4 скрипт брал все объекты `{"id":…,"categoryId"…}` на странице и считал её выдачей (82 объявления вместо 50; из-за неё сверка JSON/страница в v7.3 давала 34% при одинаковой выдаче). Запасной путь — прежний поиск всех объектов, если каталога нет. Поля: `sortTimeStamp`, `iva.FashionParamsStep` («Состояние · Размер · Бренд»), `isReserved`.
- **Лента.** Объявление новое, если `ts > lastTs` поиска. Первая проверка поиска только запоминает текущую выдачу. Непросмотренное из ленты не удаляется.
  - Объявления со старой датой заносятся в `seen` и в журнал `skipLog`.
  - **«⏪ За период»** (v7.1, вместо «Вернуть пропавшие»): окно — часы (1–168, быстрые 6/12/24/48/72), галочка «вернуть и скрытое ✓», кнопки «⏪ Бренды» / «⏪ Слова». `checkAll(…, mode, rewind = {border, hidden, hrs})`: в `checkOne` всё, что вышло после `border`, снова в «Новые» — и показанное (`shownAt`), и «просмотренное» (`seen`), и запомненное при первой проверке; скрытое ✓ (`seenAt`) — только с галочкой. Фильтры ленты работают как обычно. `lastTs` не откатывается; страницы дочитываются до `border` (до 15, `MAX_PAGES_RW`). Отметки снимаются при сохранении: `S.unhide`, `patch.seenDel`. Старый `rewindSearches` удалён: возвращал только журнал `why: 'old'`.
  - «✓ Скрыть» ставит `seenAt` на само объявление в ленте (и пишет в `seen` поиска). `seen` ограничен 500, поэтому без `seenAt` при «Всё просмотрено» на 600+ объявлений одного поиска часть оставалась в ленте.
  - Цена изменилась у объявления в ленте → `oldPrice`, в карточке «📉 было …».
  - Если вещь скрыта как «чужой бренд/размер» для своего поиска, а другой поиск находит её как свою, она переходит к этому поиску.
- **Выдача JSON-ом** (v7.3, разведка пользователя 26.10, проверено им в Chrome): `GET /web/1/js/items`. **По сети** (сжато, поправка пользователя): JSON стр. 1 — 420 КБ (2,2 МБ распаковано), стр. 2 и дальше — 184 КБ (на них нет карусели), HTML страница выдачи — 319 КБ; т.е. JSON легче в ~1,7 раза, карусель на стр. 1 — +240 КБ (~26 МБ на проверку брендов). Отключить карусель параметрами не удалось (флаги рекомендаций/рубрикатора, размер страницы, p=0); без cookie — 439. `apiUrl(url)` переводит адрес поиска: `categoryId=27`, `locationId=621540` (все регионы; без него — регион пользователя, Всеволожск 636500, и всё в `extraBlockItems`), `s=104`, `updateListOnly=true`, `d=1` (с доставкой), `pmin`/`pmax` (цена), `name` + `cd=1` (слово), `p` (страница, до 100), фильтры из кода пути `-ASg…` и `f` → `params[ID][i]` (раздел — `params[175]`, подраздел — `params[176]`). `context` не нужен. Только для адресов `/all/odezhda_obuv_aksessuary/…`, иначе — страница. Ответ разбирает тот же `parseState` (объекты объявлений такие же: `catalog.items`, `catalog.extraBlockItems`).
  - **Проверка каждого ответа** (v7.5, по `json_proverka.js` пользователя): `apiSpec(url)` — что спрашиваем, `itemsUrl` — запрос, `apiCheck(spec, json, prevIds)` сверяет `searchCore` (регион, раздел, слово, доставка, цена, сортировка, страница, каждый фильтр как набор значений) и сами объявления (больше 2 дороже лимита, больше 2 не из раздела вещей, страница повторяет предыдущую больше чем наполовину). Не сошлось на 1-й странице → `noApi: {why, at}` у поиска, он идёт страницами неделю (`API_RETRY`), потом снова пробуем JSON; на следующих страницах → дальше не листаем. Причины — в «💾 Страницы для разработчика» (`api.bad`). JSON разбирается один раз: `parseState(html, catalog)`.
  - Сверка со страницей (`apiOk` в GM, ключ `хост|вид[|q]`; v7.4 один раз сбрасывает, флаг `plan74`): первый раз для вида поисков и потом примерно 1 из 20 (`Math.random() < 0.05`) — ≥80% объявлений страницы есть в JSON → JSON (`1`), иначе страницы (`0`). Страница пустая/заготовка (<5 объявлений) — сверить нечем, сверит на следующем поиске. JSON не пришёл (404 или не JSON — например, на m.avito.ru) → `0`. Сбросить — стереть `apiOk`.
  - Через JSON нет пустых заготовок (поиск одного бренда, слово) — `seoBrandUrl`/`cd=1` нужны только для страниц.
  - **Цена — со скидкой** (v7.6, разведка пользователя 26.10, `ivaPrice`): `priceDetailed.value` — цена БЕЗ скидки; видимая цена — `iva.PriceStep`: компонент `price` (`payload.priceDetailed.value`), `discount` (`{percent, old_string}`), `saleIcon` (`tooltip.text` «Скидка до 31 декабря»). `priceWithoutDiscount`/`discountPercent` в выдаче всегда null. Фильтр Авито `pmax` считает по цене со скидкой — поэтому и `apiCheck` «дороже лимита» по ней (иначе ложная тревога на уценённых). В объявлении: `price` (со скидкой), `saleOld`, `salePct`, `saleUntil`, `priceBase`; в карточке «🏷 −45% · без скидки 9 500 ₽ · до 31 декабря». До v7.6 в ленте и ❤️ лежала цена без скидки — переход на цену со скидкой не считается «📉 подешевело» (сравнение с `priceBase`). Скидки частые: в выдаче «casadei» 10 из 50, в файле 26.10 3 из 50. Страница объявления: `buyerItem.item.formattedPrice{value, oldString, saleDiscount}`; `contactBarInfo.price` — без скидки, не брать.
  - Из выдачи берётся `isReserved` → «🔒 забронировано» в карточке. `contacts.delivery` — не признак доставки (проверено 26.10: `false` у всех 50 в поиске с `d=1`), не использовать. Описание в выдаче теперь есть у всех, но обрезано: 253 знака и «...» на конце (26.10: у 28 из 50). **v7.7:** такое описание не считается полным (`DESC_CUT`), `descCandidates` его качает; раньше правило «≥250 знаков — хватит» отсекало как раз обрезанные.
  - Файл страниц 26.10 (v7.3): JSON и страница — 50 из 50 одинаковых объявлений, тот же порядок; `searchCore` в ответе подтверждает фильтры (`withDeliveryOnly: 1`, `priceMax: 10000`, `params`).
  - **Проверка на живом Авито 26.10 (Edge пользователя, функции v7.6 на странице, запросы по одному):** одежда, обувь, аксессуары (`kupit-aksessuary`), сумки — 6 брендов, размеры, до 10 000, и слово `energie` в одежде: везде JSON = страница, 50 из 50, тот же порядок, `apiCheck` чист, `extraBlockItems` пуст. `searchCore.params[175]` приходит массивом (`[748]`) — `apiCheck` это понимает. Стр. 2 — 50 объявлений, без карусели, `page: 2`. Цены `ivaPrice` = цене в разметке страницы (`itemprop="price"`) у 50 из 50, скидок 3–15 на 50, процент совпадает с расчётом; `PriceStep` бывает ещё с компонентом `delivery` (35 из 50) — не признак доставки.
  - **Карточка объявления** — отдельного JSON нет (разведка 26.10): в HTML `window.__staticRouterHydrationData.loaderData["catalog-or-main-or-item"].buyerItem`: `item.description` (полное), `item.deliveryInfo{isDelivery, isReserved}` — точные признаки, `paramsDto.items[{attributeId, title, description}]`, `seller`, `rating`, `viewStat`. Разметка `item-view/item-description` на месте, `extractDesc` по файлу 26.10 работает (описаний ok 1886, fail 9). Проверено на живом 26.10: данные — в `JSON.parse("…")` (строка экранирована), `extractDesc` берёт описание из разметки, текст совпадает с `item.description` (там HTML с `<p>`), длинное — целиком (1 554 знака при 253 в выдаче). Цена со скидкой — `item.formattedPrice{value: 1402, oldString: "1 650", saleDiscount: "–15%", isWasLowered}`; `item.price`, `contactBarInfo.price`, `ga.*` — без скидки. Скрипт эти данные пока не читает.
  - Профиль продавца `/user/<hash>/profile` — проверено 26.10: каталога и JSON объявлений нет, в HTML только ссылки (12 у взятого продавца). Скриптом не используется.
- **Скорость.**
  - Проверка держит состояние в памяти (`newCheckState`) и сохраняет пачкой раз в 3 с. Объявление, которое уже в ленте и не изменилось, ленту не переписывает.
  - Признаки пали при разборе выдачи кэшируются (`palFeaturesMemo`): одни и те же объявления приходят при каждой проверке.
  - В ленте «✓ Скрыть», «🚫 Продавец», «✅ Не паль» убирают карточку на месте, без перерисовки; запись в хранилище — пачкой (`queueHide`, `markShown`). Есть «Отменить».
  - Чтение идёт через кэш `loadRO` / `loadFeedRO`; их результат нельзя изменять.
  - Страница поиска пересчитывается только при смене набора карточек.
  - Лента рисует карточки по 100, дальше подгружает при прокрутке.
  - Дочитывается до 8 страниц, но только если вся предыдущая страница новая.
- **Проверка — только по кнопкам** (v7.0, пользователь 25.10: «полностью убери фоновую проверку»). Нет фоновой проверки, нет проверки при открытии ленты, нет уведомлений (кнопка и настройки 🔔/🌙 убраны). Две кнопки в ленте: «🔄 Бренды» — поиски с кодом бренда, «🔎 Слова (N)» — поиски по слову без кода (`isTextSearch`: есть `q`, нет кода бренда; KENZO пользователя с кодом и словом — «Бренды»). `checkAll(…, mode)`, время — `feedMeta.lastCheck` / `lastTextCheck`. Описания для детектора пали по-прежнему качаются сами (`descRun` раз в 45 с) — это не проверка поисков.
- **Паузы Авито.** Проверка сама ждёт и продолжает (60/120/180/240 с).
- Найденное во время проверки появляется в ленте само; если лента пролистана, вместо сдвига — кнопка «⬆ Новых: N». Число новых — в заголовке вкладки.
- **⚙️ Настройки ленты** (`amsOpts`): «новое с биркой», описания, сортировка «свежие / дешёвые».
- **❤️ Отложенные** (`favItems`, до 500): копии объявлений, не зависят от ленты. Если вещь снова попалась в выдаче — цена обновляется, видно «было …». Входят в перенос и копии.
- **Клавиши в ленте (ПК):** J/K — следующее/предыдущее, O/Enter — открыть, X — скрыть, F — отложить.
- **Фильтры ленты.** Стоп-слова (общие и у каждого поиска), скрытые продавцы, размер и бренд по строке параметров, стелька по тексту.
  - Стоп-слова ищутся и в полном описании (`itemText`), латинские буквы, похожие на русские, считаются русскими (`findWord`): «пoмoжeм» с латинской «o» = «поможем». В общих стоп-словах пользователя — фразы магазинов пали («lux», «люкс», «размеры в наличии», «подобрать размер»…).
- **Детектор пали.** Вкладка «Похоже на паль», объявления не удаляются.
  - Нужно минимум два признака и 5 баллов.
  - Слабые признаки вместе дают не больше 3 баллов: новое с биркой, магазин в имени продавца, завершённые объявления.
  - Сильные признаки:
    - много размеров;
    - «реплика»;
    - продавец часто встречается в выдаче (от 5, 10, 20 раз);
    - одинаковые новые вещи по одной цене;
    - перевыложено и вещь новая;
    - вещь не в своей категории.
